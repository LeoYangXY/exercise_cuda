PTX ISA 第 11 章：伪指令（Directives）

本页由 AI 对照 NVIDIA 官方 PTX ISA 文档翻译，结合 CUDA 背景改写，仅供参考。
术语说明：本章所谓 directive（伪指令/指示符）指以 “.” 开头的 PTX 声明，用于声明程序结构（模块版本、目标架构、kernel/函数入口、状态空间、链接属性等），本身不生成机器指令。关键伪指令首次出现时给出英文与用途注释：
  • .version：声明 PTX 语言版本（每个模块开头必须有一条）。
  • .target：声明目标 sm 架构与平台选项（如 sm_90、debug）。
  • .entry：定义 kernel 入口（对应 CUDA __global__ 函数）。
  • .func：定义设备函数（对应 CUDA __device__ 函数）。
  • .param：函数参数所在的状态空间。
  • .visible / .extern / .weak：跨模块链接可见性。
  • .shared / .global / .const / .reg：状态空间（详见状态空间章节）。

Directives

PTX Module Directives

以下伪指令用于声明本模块中代码的 PTX ISA 版本、代码所面向的目标架构，以及 PTX 模块内地址的尺寸。

  • .version

  • .target

  • .address_size

PTX Module Directives: .version

.version

PTX ISA 版本号。

语法

<span></span>.version  major.minor    // major, minor are integers

说明

指定 PTX 语言版本号。

当 PTX 语言发生不兼容的变更（例如语法或语义的改变）时，主版本号（major）递增。PTX 编译器使用主版本号来保证遗留 PTX 代码能够正确执行。

当 PTX 增加新特性时，次版本号（minor）递增。

语义

表示本模块必须使用支持等于或高于该版本号的工具进行编译。

每个 PTX 模块都必须以 .version 伪指令开头，且模块内其他任何位置都不允许再出现第二条 .version 伪指令。

PTX ISA 版本说明

于 PTX ISA 1.0 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.version 3.1
.version 3.0
.version 2.3

PTX Module Directives: .target

.target

架构与平台目标。

语法

<span></span>.target stringlist         // comma separated list of target specifiers
string = { sm_120a, sm_120f, sm_120,          // sm_12x target architectures
           sm_121a, sm_121f, sm_121,          // sm_12x target architectures
           sm_110a, sm_110f, sm_110,          // sm_11x target architectures
           sm_100a, sm_100f, sm_100,          // sm_10x target architectures
           sm_101a, sm_101f, sm_101,          // sm_10x target architectures
           sm_103a, sm_103f, sm_103           // sm_10x target architectures
           sm_90a, sm_90,                     // sm_9x target architectures
           sm_80, sm_86, sm_87, sm_88, sm_89, // sm_8x target architectures
           sm_70, sm_72, sm_75,               // sm_7x target architectures
           sm_60, sm_61, sm_62,               // sm_6x target architectures
           sm_50, sm_52, sm_53,               // sm_5x target architectures
           sm_30, sm_32, sm_35, sm_37,        // sm_3x target architectures
           sm_20,                             // sm_2x target architectures
           sm_10, sm_11, sm_12, sm_13,        // sm_1x target architectures
           texmode_unified, texmode_independent,   // texturing mode
           debug,                                  // platform option
           map_f64_to_f32 };                       // platform option

说明

指定生成当前 PTX 代码所面向的目标架构特性集合。一般而言，各代 SM 架构遵循“洋葱层模型（onion layer model）”：每一代在保留前代全部特性的基础上增加新特性。洋葱层模型使得为某目标生成的 PTX 代码可以在更晚代的器件上运行。

带后缀 “a” 的目标（如 sm_90a）包含仅在该指定架构上支持的“架构专属特性”，因此这类目标不遵循洋葱层模型。为这类目标生成的 PTX 代码不能在更晚代器件上运行。架构专属特性只能用于支持这些特性的目标。

带后缀 “f” 的目标（如 sm_100f）包含仅在同一架构族内支持的“族专属特性”。因此为这类目标生成的 PTX 代码只能在同族的更晚代器件上运行。族专属特性可用于 f 目标，也可用于同族更晚代器件的 a 目标。

语义

每个 PTX 模块都必须以 .version 伪指令开头，紧接着是包含目标架构及可选平台选项的 .target 伪指令。一条 .target 伪指令指定单一目标架构，但后续可再出现 .target 伪指令以改变解析时所允许的目标特性集合。包含多条 .target 的程序只能在支持程序中所列最高编号架构全部特性的器件上编译和运行。

PTX Module Directives: .address_size

.address_size

PTX 模块全程使用的地址尺寸。

语法

<span></span>.address_size  address-size
address-size = { 32, 64 };

说明

指定 PTX 代码以及 PTX 中二进制 DWARF 信息在整个模块内所采用的地址尺寸。

模块内不允许重定义该伪指令。在分离编译场景下，所有模块必须指定（或默认采用）相同的地址尺寸。

.address_size 伪指令是可选的；但如果模块内出现，则必须紧接在 .target 伪指令之后。

语义

若省略 .address_size 伪指令，地址尺寸默认取 32。

PTX ISA 版本说明

于 PTX ISA 2.3 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>// example directives
   .address_size 32       // addresses are 32 bit
   .address_size 64       // addresses are 64 bit

// example of directive placement within a module
   .version 2.3
   .target sm_20
   .address_size 64
...
.entry foo () {
...
}

Specifying Kernel Entry Points and Functions

  • .entry

  • .func

Kernel and Function Directives: .entry

.entry

带可选参数的 kernel 入口点及函数体。

语法

<span></span>.entry kernel-name ( param-list )  kernel-body
.entry kernel-name  kernel-body

说明

为 kernel 函数定义入口点名称、参数及函数体。

参数通过 .param 状态空间内存传递，并列举在可选的圆括号参数列表中。参数可在 kernel 函数体内按名称引用，并使用 ld.param{::entry} 指令载入寄存器。

除普通参数外，不透明的 .texref、.samplerref 和 .surfref 变量也可作为参数传递。这些参数只能在纹理与表面（surface）的载入、存储及查询指令中按名称引用，不能通过 ld.param 指令访问。

执行该 kernel 的 CTA 的形状与尺寸可通过特殊寄存器获取。

语义

指定 kernel 程序的入口点。

在 kernel 启动时，kernel 的维度和属性被确定，并通过特殊寄存器（如 %ntid、%nctaid 等）提供。

PTX ISA 版本说明

对于 PTX ISA 1.4 及更高版本，参数变量在 kernel 参数列表中声明；对于 PTX ISA 1.0 至 1.3，参数变量在 kernel 函数体内声明。

PTX 对普通（非不透明类型）参数所支持的最大内存尺寸为 32764 字节。根据 PTX ISA 版本不同，参数尺寸上限也有所差异。下表展示了各 PTX ISA 版本所允许的参数尺寸：

PTX ISA 版本 最大参数尺寸（字节）

PTX ISA 8.1 及以上

32764

PTX ISA 1.5 及以上

4352

PTX ISA 1.4 及以上

256

CUDA 与 OpenCL 驱动对参数内存支持以下上限：

驱动 参数内存尺寸
CUDA

sm_1x 为 256 字节；sm_2x 及更高为 4096 字节；sm_70 及更高为 32764 字节
OpenCL

sm_70 及更高为 32764 字节；sm_6x 及更低为 4352 字节

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.entry cta_fft
.entry filter ( .param .b32 x, .param .b32 y, .param .b32 z )
{
    .reg .b32 %r&lt;99&gt;;
    ld.param.b32  %r1, [x];
    ld.param.b32  %r2, [y];
    ld.param.b32  %r3, [z];
    ...
}

.entry prefix_sum ( .param .align 4 .s32 pitch[8000] )
{
    .reg .s32 %t;
    ld.param::entry.s32  %t, [pitch];
    ...
}

Kernel and Function Directives: .func

.func

函数定义。

语法

<span></span>.func {.attribute(attr-list)} fname {.noreturn} {.abi_preserve N} {.abi_preserve_control N} function-body
.func {.attribute(attr-list)} fname (param-list) {.noreturn} {.abi_preserve N} {.abi_preserve_control N} function-body
.func {.attribute(attr-list)} (ret-param) fname (param-list) {.abi_preserve N} {.abi_preserve_control N} function-body

说明

定义一个函数，包括输入参数、返回参数以及可选的函数体。

可选的 .noreturn 伪指令表示该函数在调用后不返回。.noreturn 不能用于带返回参数的函数。参见“性能调优伪指令：.noreturn”。

可选的 .attribute 伪指令指定与函数相关的附加信息。允许的属性见“变量与函数属性伪指令：.attribute”。

可选的 .abi_preserve 与 .abi_preserve_control 伪指令用于指定通用寄存器与控制寄存器的数量。详见“性能调优伪指令：.abi_preserve”与“.abi_preserve_control”。

若函数指定了任何伪指令（如 .noreturn），则必须在函数声明与定义中保持一致。

没有函数体的 .func 定义即为函数原型。

参数列表定义函数体内的局部作用域变量。参数必须是寄存器或参数状态空间中的基类型。寄存器状态空间中的参数可在函数体指令中直接引用；.param 状态空间中的参数通过函数体内的 ld.param{::func} 与 st.param{::func} 指令访问。参数传递采用值传递（call-by-value）。

参数列表的最后一个参数可以是一个未指定尺寸的 .b8 类型 .param 数组，用于将任意数量的参数打包进单个数组对象传递给函数。

调用带有此类未定尺寸末参数的函数时，若没有任何参数通过该数组传递，则 call 指令中可以省略末参数。对该数组参数的访问必须落在数组边界内；若未传入数组，或访问越界，则结果是未定义的。

语义

PTX 语法隐藏了底层调用约定与 ABI 的所有细节。

参数传递的具体实现交由优化翻译器决定，它可以使用寄存器与栈位置的组合来传递参数。

发布说明

对于 PTX ISA 1.x 代码，参数必须位于寄存器状态空间，没有栈，且不允许递归。

PTX ISA 2.0 及更高版本、且目标为 sm_20 或更高时，允许参数位于 .param 状态空间，实现带栈的 ABI，并支持递归。

PTX ISA 2.0 及更高版本、且目标为 sm_20 或更高时，最多支持一个返回值。

PTX ISA 版本说明

于 PTX ISA 1.0 引入。

未定尺寸数组参数的支持于 PTX ISA 6.0 引入。

.noreturn 伪指令的支持于 PTX ISA 6.4 引入。

.attribute 伪指令的支持于 PTX ISA 8.0 引入。

.abi_preserve 与 .abi_preserve_control 伪指令的支持于 PTX ISA 9.0 引入。

目标 ISA 说明

不带未定尺寸数组参数的函数在所有目标架构上均支持。

未定尺寸数组参数需要 sm_30 或更高。

.noreturn 伪指令需要 sm_30 或更高。

.attribute 伪指令需要 sm_90 或更高。

.abi_preserve 与 .abi_preserve_control 伪指令需要 sm_80 或更高。

示例

<span></span>.func (.reg .b32 rval) foo (.reg .b32 N, .reg .f64 dbl)
{
.reg .b32 localVar;

... use N, dbl;
other code;

mov.b32 rval,result;
ret;
}

...
call (fooval), foo, (val0, val1);  // return value in fooval
...

.func foo (.reg .b32 N, .reg .f64 dbl) .noreturn
{
.reg .b32 localVar;
... use N, dbl;
other code;
mov.b32 rval, result;
ret;
}
...
call foo, (val0, val1);
...

.func (.param .u32 rval) bar(.param .u32 N, .param .align 4 .b8 numbers[])
{
    .reg .b32 input0, input1;
    ld.param.b32   input0, [numbers + 0];

Performance-Tuning Directives

为提供底层性能调优机制，PTX 支持以下伪指令，它们把信息传递给优化后端编译器。

  • .maxnreg

  • .maxntid

  • .reqntid

  • .minnctapersm

  • .maxnctapersm（已废弃）

  • .pragma

  • .abi_preserve

  • .abi_preserve_control

.maxnreg 伪指令指定分配给单个线程的最大寄存器数；.maxntid 指定线程块（CTA）内的最大线程数；.reqntid 指定线程块（CTA）所需的线程数；.minnctapersm 指定调度到单个多处理器（SM）上的最小线程块数。这些可用于例如限制资源需求（如寄存器）以提升总线程数、增大隐藏内存延迟的机会。.minnctapersm 可与 .maxntid 或 .reqntid 配合使用，在“每线程寄存器数”与“多处理器利用率”之间做权衡，而无需直接指定最大寄存器数；在面向每 SM 寄存器数不同的多器件编译 PTX 时可能获得更好性能。

设备函数伪指令 .abi_preserve 与 .abi_preserve_control 指定函数必须为其调用者保留的、来自被调用者保存（callee-save）寄存器的数据与控制寄存器数量。可理解为函数被调用时调用者中仍然存活的通用寄存器与控制寄存器数量。控制寄存器指导致当前函数调用的调用树（calltree）中出现的分叉程序点数量。

目前，.maxnreg、.maxntid、.reqntid 与 .minnctapersm 伪指令可按入口（per-entry）应用，且必须出现在 .entry 伪指令与其函数体之间。这些伪指令优先于传递给优化后端的任何模块级约束。若这些伪指令的约束相互矛盾，或对所指定的目标器件无法满足，则会产生警告信息。

支持通用的 .pragma 伪指令以向 PTX 后端传递信息。该伪指令向后端传递一组字符串，这些字符串在 PTX 虚拟机模型中没有语义。.pragma 值的解释由后端实现决定，不在 PTX ISA 范畴内。注意 .pragma 伪指令可出现在模块（文件）作用域、入口作用域，或作为 kernel/设备函数体内的语句。

Performance-Tuning Directives: .maxnreg

.maxnreg

每个线程可分配的最大寄存器数。

语法

<span></span>.maxnreg n

说明

声明 CTA 中每个线程的最大寄存器数。

语义

编译器保证不超过此上限。实际使用的寄存器数可能更少——例如后端可能编译出更少的寄存器，或最大寄存器数被 .maxntid 与 .maxctapersm 进一步约束。

PTX ISA 版本说明

于 PTX ISA 1.3 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.entry foo .maxnreg 16 { ... }  // max regs per thread = 16

Performance-Tuning Directives: .maxntid

.maxntid

线程块（CTA）内的最大线程数。

语法

<span></span>.maxntid nx
.maxntid nx, ny
.maxntid nx, ny, nz

说明

声明线程块（CTA）内的最大线程数。该最大值通过给出 1D、2D 或 3D CTA 各维的最大跨度来指定，最大线程数即各维最大跨度的乘积。

语义

线程块的最大线程数（即各维最大跨度的乘积）保证在本伪指令所在 kernel 的任何一次调用中都不会被超过。超过最大线程数会导致运行时错误或 kernel 启动失败。

注意该伪指令只保证线程总数不超过最大值，并不保证某一特定维度的上限不被超过。

PTX ISA 版本说明

于 PTX ISA 1.3 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.entry foo .maxntid 256       { ... }  // max threads = 256
.entry bar .maxntid 16,16,4   { ... }  // max threads = 1024

Performance-Tuning Directives: .reqntid

.reqntid

线程块（CTA）内的线程数。

语法

<span></span>.reqntid nx
.reqntid nx, ny
.reqntid nx, ny, nz

说明

通过指定 1D、2D 或 3D CTA 各维的跨度来声明线程块（CTA）内的线程数。总线程数为各维线程数的乘积。

语义

kernel 任何一次调用中所指定的各 CTA 维度大小必须等于本伪指令所指定的值。启动时指定不同的 CTA 维度会导致运行时错误或 kernel 启动失败。

备注

.reqntid 伪指令不能与 .maxntid 伪指令同时使用。

PTX ISA 版本说明

于 PTX ISA 2.1 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.entry foo .reqntid 256       { ... }  // num threads = 256
.entry bar .reqntid 16,16,4   { ... }  // num threads = 1024

Performance-Tuning Directives: .minnctapersm

.minnctapersm

每个 SM 的最小 CTA 数。

语法

<span></span>.minnctapersm ncta

说明

声明 kernel 的网格中映射到单个多处理器（SM）的最小 CTA 数。

备注

基于 .minnctapersm 的优化还需要同时指定 .maxntid 或 .reqntid。

若由 .minnctapersm 与 .maxntid/.reqntid 得出的单个 SM 上的总线程数超过 SM 支持的最大线程数，则 .minnctapersm 伪指令会被忽略。

在 PTX ISA 2.1 或更高版本中，若指定了 .minnctapersm 却未指定 .maxntid 或 .reqntid，会产生警告。

PTX ISA 版本说明

于 PTX ISA 2.0 引入，作为 .maxnctapersm 的替代。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.entry foo .maxntid 256 .minnctapersm 4 { ... }

Performance-Tuning Directives: .maxnctapersm (deprecated)

.maxnctapersm

每个 SM 的最大 CTA 数。

语法

<span></span>.maxnctapersm ncta

说明

声明 kernel 的网格中可映射到单个多处理器（SM）的最大 CTA 数。

备注

基于 .maxnctapersm 的优化通常也需要指定 .maxntid。优化后端编译器使用 .maxntid 与 .maxnctapersm 计算每线程寄存器用量的上界，以便将指定数量的 CTA 映射到单个多处理器。但若后端实际使用的寄存器数远低于该上界，可能会有更多 CTA 被映射到一个多处理器。因此，在 PTX ISA 2.0 中 .maxnctapersm 已被重命名为 .minnctapersm。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.entry foo .maxntid 256 .maxnctapersm 4 { ... }

Performance-Tuning Directives: .abi_preserve

.abi_preserve

指定该函数的调用者应当保留的通用寄存器数量。

语法

<span></span>.abi_preserve N

说明

这是一个与架构无关的值，表示实际的通用寄存器数量。ABI 内部将部分通用寄存器定义为被保留（callee-save）寄存器。整数 N 指定该函数应当保留的实际通用寄存器数量。

.abi_preserve 伪指令只能用于设备函数，且必须出现在 .func 伪指令与其函数体之间。

语义

指定该伪指令后，编译器后端会修改底层 ABI 组件，确保该函数调用者中存放在 callee-save 寄存器内的存活数据变量数小于指定值。

PTX ISA 版本说明

于 PTX ISA 9.0 引入。

目标 ISA 说明

需要 sm_80 或更高。

示例

<span></span>.func bar() .abi_preserve 8

// Indirect call via call prototype
.func (.param .b32 out[30]) foo (.param .b32 in[30]) .abi_preserve 10 { ... }
...
mov.b64 lpfoo, foo;
prot: .callprototype (.param .b32 out[30]) _ (.param .b32 in[30]) .abi_preserve 10;
call (out), lpfoo, (in), prot;

Debugging Directives: .section

.section

PTX 段（section）定义。

语法

                         // in range [-128..255]

                         // in range [-2^15..2^16-1]

  .b64   label+imm       // a sum of label address plus a constant integer byte

  .b64   label3-label4   // a difference in label addresses between labels in

    .b8 -11, 11, 112, 97
    .b32 info_label1+12
    .b64 -1
    .b16 -5, -65535
}

Debugging Directives: .file

.file

源文件名。

语法

<span></span>.file file_index "filename" {, timestamp, file_size}

说明

将一个源文件名与一个整数索引关联。.loc 伪指令通过该索引引用源文件。

.file 伪指令允许可选地指定一个表示最后修改时间的无符号数，以及一个表示源文件字节大小的无符号整数。timestamp 与 file_size 可以为 0，表示此信息不可用。

timestamp 值采用 C/C++ 的 time_t 类型格式。

file_size 是无符号 64 位整数。

.file 伪指令只允许出现在最外层作用域，即与 kernel 及设备函数声明同级。

语义

若未指定 timestamp 与 file_size，则默认取 0。

PTX ISA 版本说明

于 PTX ISA 1.0 引入。

timestamp 与 file_size 于 PTX ISA 3.2 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.file 1 "example.cu"
.file 2 "kernel.cu"
.file 1 "kernel.cu", 1339013327, 64118

Debugging Directives: .loc

.loc

源文件位置。

语法

<span></span>.loc file_index line_number column_position
.loc file_index line_number column_position,function_name label {+ immediate }, inlined_at file_index2 line_number2 column_position2

说明

声明与词法上后续 PTX 指令相关联的源文件位置（源文件、行号、列位置）。.loc 引用的 file_index 由 .file 伪指令定义。

为标明由被内联函数生成的 PTX 指令，可在 .loc 伪指令中指定附加属性 .inlined_at，它表示该函数被内联处的源位置。file_index2、line_number2、column_position2 指定函数被内联的位置。.inlined_at 所指定的源位置必须在词法上早于 .loc 伪指令中的源位置。

function_name 属性指定 .debug_str 段中的偏移量，以 label 表达式或 label + 立即数表达式给出，其中 label 定义于 .debug_str 段。.debug_str 段包含以 ASCII 空字符结尾的字符串，表示被内联函数的名称。

注意一条 PTX 指令最多有一个相关联的源位置，由词法上最近的前驱 .loc 伪指令决定；若无前驱 .loc 则无关联源位置。PTX 中的标号继承其词法上最接近的后续指令的位置；没有后续 PTX 指令的标号则无关联源位置。

PTX ISA 版本说明

于 PTX ISA 1.0 引入。

function_name 与 inlined_at 属性于 PTX ISA 7.2 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>    .loc 2 4237 0
L1:                        // line 4237, col 0 of file #2,
                           // inherited from mov
    mov.u32  %r1,%r2;      // line 4237, col 0 of file #2
    add.u32  %r2,%r1,%r3;  // line 4237, col 0 of file #2
...
L2:                        // line 4239, col 5 of file #2,
                           // inherited from sub
    .loc 2 4239 5
    sub.u32  %r2,%r1,%r3;  // line 4239, col 5 of file #2
    .loc 1 21 3
    .loc 1 9 3, function_name info_string0, inlined_at 1 21 3
    ld.global.u32   %r1, [gg]; // Function at line 9
    setp.lt.s32 %p1, %r1, 8;   // inlined at line 21
    .loc 1 27 3
    .loc 1 10 5, function_name info_string1, inlined_at 1 27 3
    .loc 1 15 3, function_name .debug_str+16, inlined_at 1 10 5
    setp.ne.s32 %p2, %r1, 18;
    @%p2 bra    BB2_3;

    .section .debug_str {
    info_string0:
     .b8 95  // _
     .b8 90  // z
     .b8 51  // 3
     .b8 102 // f
     .b8 111 // o
     .b8 111 // o
     .b8 118 // v
     .b8 0

    info_string1:
     .b8 95  // _
     .b8 90  // z
     .b8 51  // 3
     .b8 98  // b
     .b8 97  // a
     .b8 114 // r

    }

.visible

（对外）可见符号声明。

语法

<span></span>.visible identifier

说明

声明标识符为全局可见。与 C 不同（C 中除非声明为 static 否则标识符全局可见），PTX 标识符默认仅在当前模块内可见，除非在当前模块之外声明为 .visible。

PTX ISA 版本说明

于 PTX ISA 1.0 引入。

目标 ISA 说明

所有目标架构均支持。

<span></span>.visible .global .b32 foo;  // foo will be externally visible

Linking Directives: .weak

.weak

（对外）可见符号声明。

语法

<span></span>.weak identifier

说明

声明标识符为全局可见但为弱符号（weak）。弱符号与全局可见符号类似，但在链接时，符号解析中弱符号仅在全局可见符号之后才会被选用。与全局可见符号不同，多个目标文件可声明同一弱符号，且只有当没有同名全局符号时，对该符号的引用才解析到弱符号。

PTX ISA 版本说明

于 PTX ISA 3.1 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.weak .func (.reg .b32 val) foo;  // foo will be externally visible

Linking Directives: .common

.common

（对外）可见符号声明。

语法

<span></span>.common identifier

说明

声明标识符为全局可见但属于“common”符号。

common 符号与全局可见符号类似，但多个目标文件可声明同一 common 符号，且它们可以具有不同类型与尺寸；对该符号的引用会解析到尺寸最大的 common 符号。

只有一个目标文件可以初始化 common 符号，且其尺寸必须是来自不同目标文件的所有该 common 符号定义中最大的。

.common 链接伪指令只能用于具有 .global 存储的变量，不能用于函数符号或不透明类型的符号。

PTX ISA 版本说明

于 PTX ISA 5.0 引入。

目标 ISA 说明

.common 伪指令需要 sm_20 或更高。

示例

<span></span>.common .global .u32 gbl;

Cluster Dimension Directives

以下伪指令用于指定关于簇（cluster）的信息：

  • .reqnctapercluster

  • .explicitcluster

  • .maxclusterrank

.reqnctapercluster 伪指令指定簇中的 CTA 数；.explicitcluster 指定 kernel 应以显式簇信息启动；.maxclusterrank 指定簇中 CTA 的最大数量。

簇维度伪指令只能用于 kernel 函数。

Cluster Dimension Directives: .reqnctapercluster

.reqnctapercluster

声明簇中的 CTA 数量。

语法

<span></span>.reqnctapercluster nx
.reqnctapercluster nx, ny
.reqnctapercluster nx, ny, nz

说明

通过指定 1D、2D 或 3D 簇各维的跨度来设定簇中的线程块（CTA）数。CTA 总数为各维 CTA 数的乘积。对于指定了 .reqnctapercluster 的 kernel，若启动时未指定相应值，运行时将使用此处指定的值来配置启动。

语义

若在启动时显式指定了簇维度，则必须等于本伪指令所指定的值。启动时指定不同的簇维度会导致运行时错误或 kernel 启动失败。

PTX ISA 版本说明

于 PTX ISA 7.8 引入。

目标 ISA 说明

需要 sm_90 或更高。

示例

<span></span>.entry foo .reqnctapercluster 2         { . . . }
.entry bar .reqnctapercluster 2, 2, 1   { . . . }
.entry ker .reqnctapercluster 3, 2      { . . . }

Cluster Dimension Directives: .explicitcluster

.explicitcluster

声明 kernel 必须以显式指定的簇维度启动。

语法

<span></span>.explicitcluster

说明

声明该 kernel 应以显式指定的簇维度启动。

语义

带有 .explicitcluster 的 kernel 必须以显式指定的簇维度启动（启动时指定或通过 .reqnctapercluster），否则程序会因运行时错误或 kernel 启动失败而失败。

PTX ISA 版本说明

于 PTX ISA 7.8 引入。

目标 ISA 说明

需要 sm_90 或更高。

示例

<span></span>.entry foo .explicitcluster         { . . . }

Cluster Dimension Directives: .maxclusterrank

.maxclusterrank

声明可作为簇一部分的 CTA 的最大数量。

语法

<span></span>.maxclusterrank n

说明

声明允许作为簇一部分的线程块（CTA）的最大数量。

语义

kernel 任何一次调用中各簇维度 CTA 数的乘积必须小于或等于本伪指令所指定的值，否则调用会导致运行时错误或 kernel 启动失败。

.maxclusterrank 伪指令不能与 .reqnctapercluster 伪指令同时使用。

PTX ISA 版本说明

于 PTX ISA 7.8 引入。

目标 ISA 说明

需要 sm_90 或更高。

示例

<span></span>.entry foo ..maxclusterrank 8         { . . . }

Miscellaneous Directives

PTX 提供以下其他伪指令：

Miscellaneous Directives: .blocksareclusters

.blocksareclusters

指定 CUDA 线程块被映射到簇。

语法

<span></span>.blocksareclusters

说明

CUDA API 的默认行为是通过指定线程块数与每块的线程数来配置网格启动。

当指定了 .blocksareclusters 时，意味着对应 .entry 函数的网格启动配置是在指定簇的数量——即启动配置指定的是簇数而非线程块数。此时每簇的线程块数由 .reqnctapercluster 指定，线程块尺寸由 .reqntid 指定。

.blocksareclusters 伪指令只允许用于 .entry 函数，且还需要指定 .reqntid 与 .reqnctapercluster 伪指令。

更多细节请参阅《CUDA 编程指南》。

PTX ISA 版本说明

于 PTX ISA 9.0 引入。

目标 ISA 说明

需要 sm_90 或更高。

示例

<span></span>.entry foo .reqntid 32, 32, 1 .reqnctapercluster 32, 32, 1 .blocksareclusters { ... }

Miscellaneous Directives: .language

.language

指定用于生成该 kernel 或函数的源语言。

语法

<span></span>.language lang-list   // comma separated list of strings or integers

说明

.language 伪指令声明生成对应 .entry 或 .func 函数代码的源语言。该伪指令接受以逗号分隔的语言代码列表，可以是带引号的字符串名或无符号整数值。

.language 伪指令允许用于 .entry 与 .func 函数，且必须出现在函数伪指令与其函数体之间。

若未指定 .language 伪指令，则语言默认为 "ptx"。

可为单个函数指定多种语言，表示混合语言来源。语言名不区分大小写。

以无符号整数指定的语言代码必须在 [0..10] 范围内。字符串名与整数代码的映射如下：

代码 字符串

0

“unknown”（未知）

1

保留（Reserved）

2

保留（Reserved）

3

“ptx”（PTX 汇编本身）

4

“nvvm”（NVVM IR）

5

“cuda c++”（CUDA C++）

6

“cuda c++ tile”（CUDA C++ Tile）

7

“tile ir”（Tile IR）

8

“python-cutile”（Python cuTile）

9

“fortran”（Fortran）

10

“optix”（OptiX）

PTX ISA 版本说明

于 PTX ISA 9.3 引入。

目标 ISA 说明

所有目标架构均支持。

示例

<span></span>.entry foo () .language "ptx"                    { ... }
.func bar ()  .language "nvvm", "ptx"            { ... }
.entry baz () .language "ptx", "cuda c++", 0x7   { ... }
