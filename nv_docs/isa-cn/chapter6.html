术语说明（结合 CUDA/PTX 背景）：PTX 指令的标准形式通常写作 op.type d, a, b;，其中 op 为操作码、type 为数据类型、 d 为目的操作数（destination）、a,b 等为源操作数（source）。 下文首次出现的关键术语将给出英文原文与简要解释。

6.1 操作数类型信息（Operand Type Information）

指令中的所有 operand（操作数） 都拥有由其声明所确定的已知类型。 每个操作数的类型都必须与“指令模板（instruction template）”以及“指令类型（instruction type）”所确定的类型相兼容。 PTX 不会在类型之间做任何自动转换。

bit-size 类型（即以比特位宽命名的类型，如 .b32、.b64）与任何相同位宽的类型兼容； 相同位宽的整数类型彼此之间也互相兼容。当某个操作数的类型与指令类型不同、但彼此兼容时，它会被“静默地（silently）”转换为指令类型。

6.2 源操作数（Source Operands）

在指令描述中，源操作数（source operands）用字母 a、b、c 来标记。 PTX 描述的是一种“加载–存储（load-store）”型机器，因此 ALU 指令的操作数必须全部位于 .reg 寄存器状态空间（register state space）中声明的变量里。 对大多数运算而言，各操作数的位宽必须保持一致。

cvt（convert，转换）指令接受多种不同的操作数类型与位宽，因为它的职责正是把几乎任意数据类型转换为另一种数据类型（含位宽变化）。 ld、st、mov 与 cvt 指令负责把数据从一个位置复制到另一个位置：

  • ld 与 st：把数据在“可寻址状态空间（addressable state spaces）”与寄存器之间来回搬移；
  • mov：在寄存器之间复制数据。

大多数指令都带有一个可选的 predicate operand（谓词操作数，即 @p 形式的条件执行）， 用于控制条件执行；还有少数指令带有额外的谓词型源操作数。谓词操作数用字母 p、q、r、s 标记。

6.3 目的操作数（Destination Operands）

产生单一结果的 PTX 指令，会把结果存入指令描述中标记为 d（destination，目的）的字段。 该结果操作数是一个位于寄存器状态空间中的标量（scalar）或向量（vector）变量。

6.4 使用地址、数组与向量（Using Addresses, Arrays, and Vectors）

把标量变量直接当作操作数使用是非常直观的；真正有趣的能力始于地址、数组与向量。

6.4.1 地址作为操作数（Addresses as Operands）

所有的访存指令（memory instructions）都接受一个地址操作数（address operand），用来指明被访问的内存位置。 这种 addressable operand（可寻址操作数） 可以是以下几种形式之一：

  • [var]：一个可寻址变量 var 的名字；
  • [reg]：一个包含“字节地址（byte address）”的寄存器 reg，其类型为整型或 bit-size 类型；
  • [reg+immOff]：包含字节地址的寄存器 reg 加上一个常量整数字节偏移（有符号，32 位）之和；
  • [var+immOff]：可寻址变量 var 的地址加上一个常量整数字节偏移（有符号，32 位）之和；
  • [immAddr]：一个立即数绝对字节地址（无符号，32 位）；
  • var[immOff]：一个数组元素，详见下文“数组作为操作数”。

存放地址的寄存器可以声明为 bit-size 类型或整型。一条访存指令的 访问宽度（access size） 是指它在内存中实际访问的字节总数。例如，ld.v4.b32 的访问宽度是 16 字节， 而 atom.f16x2 的访问宽度是 4 字节。地址必须按访问宽度的整数倍进行“自然对齐（naturally aligned）”。 如果地址未正确对齐，其行为是未定义的（undefined）——比如访问可能通过悄悄屏蔽低位地址位来实现对齐， 也可能直接触发异常（fault）。

地址宽度可以是 32 位或 64 位，不支持 128 位地址。地址会按需零扩展（zero-extended）到指定宽度； 若寄存器宽度超过目标架构对应状态空间的地址宽度，则会被截断。

地址运算使用整数算术与逻辑指令完成（例如指针运算、指针比较）。所有地址及地址计算都以字节（byte）为单位， 不支持 C 语言风格的“按类型大小”指针算术（即 p+1 不会自动乘以元素大小）。 mov 指令可以把一个变量的地址搬入指针寄存器；该地址是变量所声明状态空间内的一个偏移量。

加载（load）与存储（store）操作在寄存器与可寻址状态空间中的位置之间搬移数据，语法与许多汇编语言类似： 标量变量直接写名字，地址则用方括号把 address expression（地址表达式，如 [r1] 或 a[r1]） 括起来进行解引用。 地址表达式包括：变量名、地址寄存器、地址寄存器加字节偏移，以及能在编译期求值为常量地址的立即数地址表达式。示例如下： 

.shared .u16 x;          // 在 shared 空间声明 u16 变量 x
.reg .u16 r0;            // 声明 u16 寄存器 r0
.global .v4 .f32 V;      // 在 global 空间声明 v4.f32 向量变量 V
.reg .v4 .f32 W;         // 声明 v4.f32 向量寄存器 W
.const .s32 tbl[256];    // 在 const 空间声明含 256 个 s32 的数组 tbl
.reg .b32 p;             // 声明 b32 寄存器 p（可当指针用）
.reg .s32 q;             // 声明 s32 寄存器 q

ld.shared.u16 r0, [x];   // 从 shared 加载 x 到 r0
ld.global.v4.f32 W, [V]; // 从 global 以向量方式加载 V 到 W
ld.const.s32 q, [tbl+12];// 从 const 数组 tbl 偏移 12 字节处加载到 q
mov.u32 p, tbl;          // 把数组 tbl 的地址（偏移量）搬入 p

6.4.1.1 通用寻址（Generic Addressing）

如果一条访存指令没有显式指定状态空间，则使用 generic addressing（通用寻址） 方式执行。 状态空间 .const、Kernel 函数参数（.param）、.local 与 .shared 在通用地址空间（generic address space）中被建模为若干个“窗口（window）”。 每个窗口由“窗口基址（window base）”和“窗口大小（window size）”定义，窗口大小等于对应状态空间的大小。

一个通用地址会被映射到 global 内存，除非它落在 .const、.local 或 .shared 内存的窗口范围内。 Kernel 函数参数（.param）窗口包含在 .global 窗口之内。在每个窗口内部， 通用地址通过“减去窗口基址”来映射到底层状态空间中的真实地址。

6.4.2 数组作为操作数（Arrays as Operands）

可以声明任意类型的数组，数组名会成为一个“数组所声明空间内的地址常量”，数组大小是程序中的常量。 数组元素既可以通过显式计算出的字节地址访问，也可以用方括号下标（indexing）方式索引访问。 方括号内的表达式可以是：一个常量整数、一个寄存器变量，或一个“寄存器加常量偏移”的简单表达式 （偏移量是与寄存器变量相加或相减的常量表达式）。如果需要更复杂的索引，必须先把它写成一次地址计算，再用于访问。示例如下： 

ld.global.u32 s, a[0];     // 加载数组 a 的第 0 个元素
ld.global.u32 s, a[N-1];   // 加载数组 a 的最后一个元素（N 为常量）
mov.u32 s, a[1];           // 把 a[1] 的地址搬入 s（注意：是地址，不是值）

6.4.3 向量作为操作数（Vectors as Operands）

向量操作数（vector operands）可以作为指令的源操作数和目的操作数来使用。 但当它作为目的操作数时，向量表达式中的所有元素必须互不相同，否则行为未定义。 向量也可以作为被调用函数的参数传递。向量元素可通过后缀 .x、.y、.z、.w 以及典型的颜色分量字段 .r、.g、.b、.a 来提取。 花括号包围的列表（brace-enclosed list）用于模式匹配，以拆解向量。例如： 

.reg .v4 .f32 V;        // 声明 v4.f32 向量寄存器 V
.reg .f32 a, b, c, d;   // 声明 4 个标量 f32 寄存器
mov.v4.f32 {a,b,c,d}, V;// 把向量 V 的 4 个元素分别存入 a,b,c,d

向量加载与存储可用于实现“宽加载/宽存储（wide loads and stores）”，从而提升访存性能。 在加载/存储操作中，寄存器既可以是一个向量，也可以是花括号包围的、类型相同的标量列表。例如： 

ld.global.v4.f32 {a,b,c,d}, [addr+16];  // 宽加载 4 个 f32（共 16 字节）
ld.global.v2.u32 V2, [addr+8];         // 以 v2 向量方式加载 2 个 u32

花括号向量（如 {Ra, Rb, Rc, Rd}）中的元素与提取分量的对应关系如下： 

Ra = V.x = V.r
Rb = V.y = V.g
Rc = V.z = V.b
Rd = V.w = V.a

6.4.4 标签与函数名作为操作数（Labels and Function Names as Operands）

标签（labels）只能用于 bra / brx.idx 指令；函数名（function names）只能用于 call 指令。 函数名可以在 mov 指令中使用，以便把函数地址取入寄存器，供间接调用（indirect call）使用。

从 PTX ISA 3.1 版本开始，mov 指令还可以用来获取 kernel 函数的地址， 以便传给某个系统调用、从而从 GPU 上发起 kernel 启动（kernel launch）。这是 CUDA 动态并行（Dynamic Parallelism） 支持的一部分，详见《CUDA Dynamic Parallelism Programming Guide》。

6.5 类型转换（Type Conversion）

除了那些“改变大小或类型是指令定义本身一部分”的运算外，所有算术、逻辑与数据搬移指令的操作数都必须具有相同的类型与位宽。 位宽或类型不同的操作数，必须在运算之前先完成转换。

6.6 操作数开销（Operand Costs）

来自不同状态空间的操作数会影响运算的速度。寄存器最快，而 global 内存最慢。 访存带来的大量延迟可以通过多种方式隐藏：

  • 一是让多个执行线程并行——硬件可以发起一次访存操作后，切换到其它线程去执行；
  • 另一种隐藏延迟的方法是尽早发出加载指令，因为在后续（按时间顺序）真正用到该结果之前，执行并不会被阻塞；
  • 存储（store）操作中的寄存器会快得多地被释放出来可用。
