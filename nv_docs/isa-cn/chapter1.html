第 1 章 引言 Introduction — PTX ISA 9.3

本文件描述的是 PTX（Parallel Thread Execution，并行线程执行——一种虚拟指令集架构）。PTX 是一套底层的、以并行线程执行为核心的虚拟机与 ISA（Instruction Set Architecture，指令集架构）。借助 PTX，GPU 被暴露成一个数据并行（data-parallel）的计算设备（device）。

结合 CUDA 理解：在 CUDA 编程模型里，开发者用 C/C++ 写出 __global__ 函数（即 kernel，核函数），编译器并不直接生成某个具体 GPU 的机器码，而是先生成 PTX 这种"虚拟汇编"。PTX 之所以是"虚拟"的，是因为它不绑定任何特定的硬件——它描述的是一种理想化的并行计算模型，真正落到某代 GPU 的机器码，是在程序安装/运行时由驱动中的 JIT 编译器完成的。把 GPU 看作"数据并行设备"，正是 PTX 设计的出发点：你告诉它"对一大批数据并行地做同一件事"，它负责把这事映射到硬件上。

1.1 用 GPU 实现可扩展的数据并行计算

在实时高清 3D 图形这种永不满足的市场需求驱动下，可编程 GPU 已经演变成高度并行、多线程、众核（many-core）的处理器，拥有惊人的算力与极高的内存带宽。GPU 尤其擅长处理这样一类问题：它们可以被表达为数据并行计算——即同一个程序被并行地施加到大量数据元素之上——并且具有高算术强度（arithmetic intensity），也就是算术运算量与内存访问量的比值很高。由于每个数据元素执行的都是同一份程序，所以对复杂流控（flow control）的需求很低；又因为程序作用于海量数据元素且算术强度高，内存访问的延迟可以通过计算来"掩盖"，而无需依赖庞大的数据缓存。

数据并行处理的核心思想，是把数据元素映射到并行的处理线程上。许多处理大型数据集的应用，都可以借助数据并行编程模型来加速计算。在 3D 渲染中，海量的像素与顶点被映射到并行线程；类似地，图像处理与媒体处理类应用——例如渲染后处理、视频编解码、图像缩放、立体视觉、模式识别等——也能把图像块与像素映射到并行线程。事实上，在图像渲染与处理领域之外，也有大量算法因数据并行处理而获得加速，从通用的信号处理、物理仿真，到计算金融、计算生物学，莫不如此。

PTX 定义的是一套用于通用并行线程执行的虚拟机与 ISA。PTX 程序会在安装时（install time）被翻译为目标硬件的指令集。正是有了 PTX 到 GPU 的翻译器与驱动，NVIDIA GPU 才得以作为可编程的并行计算机来使用。

对应到 CUDA："数据并行"正是 CUDA 编程的并行执行模型的本质——你写一个 kernel，然后用成千上万个线程同时调用它，每个线程处理数据的一个切片（比如一个像素、一个矩阵元素）。grid、block、thread 这套层次，正是对"把数据元素映射到并行线程"这一思想的系统化封装。而"高算术强度可以掩盖内存延迟"这一点，是 CUDA 性能优化的核心直觉：与其等内存，不如让线程去算别的东西，这正是 GPU 不靠大缓存、而靠"切换就绪线程"来隐藏延迟的设计哲学。

1.2 PTX 的目标

PTX 为通用并行编程提供了一套稳定的编程模型与指令集。它被设计成在支持 NVIDIA Tesla 架构所定义计算特性的 NVIDIA GPU 上高效运行。像 CUDA 与 C/C++ 这样的高级语言编译器，会生成 PTX 指令；这些指令经过优化，并进一步翻译为目标架构的原生指令。

PTX 的目标包括以下几点：

  • 提供一套跨越多代 GPU 的稳定 ISA。
  • 使编译后应用的性能逼近原生 GPU 性能。
  • 为 C/C++ 及其他编译器提供一套与机器无关（machine-independent） 的 ISA 作为编译目标。
  • 为应用与中间件开发者提供一套代码分发（code distribution） 用的 ISA。
  • 为把 PTX 映射到具体目标机器的各种优化代码生成器与翻译器，提供一套通用的源级 ISA。
  • 方便手工编写库、性能关键 kernel 以及架构测试程序。
  • 提供一套可扩展的编程模型，其规模可从单个 GPU 单元一路覆盖到众多并行单元。
设计意图："跨越多代 GPU 稳定"是 PTX 存在的最大价值。CUDA 程序一次编译出的 PTX，可以在不同架构（如 sm_70、sm_80、sm_90）的 GPU 上由驱动重新 JIT 成对应机器码，开发者无需为每代硬件重写底层代码。而"与机器无关的 ISA"则意味着：不仅 CUDA C++ 编译器，其他语言的前端、甚至手写汇编优化，都可以以 PTX 作为统一的输出/输入格式。

1.3 PTX ISA 第 9.3 版

PTX ISA 9.3 版引入了以下新特性：

  • 新增对 mma_throughput pragma（编译指示）的支持。
  • 新增对 clmad 指令的支持。
  • 为 mbarrier.test_wait 与 mbarrier.try_wait 指令新增 .phase_type::* 限定符。
  • 为 mbarrier.test_wait 与 mbarrier.try_wait 指令新增 reportPredicate 与 reportValue 操作数。
  • 为 mbarrier 指令新增 .layout 限定符，并新增 mbarrier.check_layout 指令。
  • 新增 multimem.st.async 与 multimem.red.async 指令。
  • 为 cp.async.bulk、cp.reduce.async.bulk、multimem.cp.async.bulk 与 multimem.cp.reduce.async.bulk 指令新增 .sem 与 .scope 限定符。
  • 新增 fabric.try_get、fabric.try_put、fabric.try_red、fabric.try_pullred、fabric.wait、fabric.submit 指令。
  • 为 fence 指令新增 fence.proxy.to_proxykind::from_proxykind_fabric 限定符。
  • 新增 .language 指令（directive）。
背景补充：这一长串新增特性大多面向 Hopper（sm_90）及更新的架构，集中在几个方面：mbarrier 系列与线程束屏障/集群同步有关；multimem 与 cp.async.bulk 涉及跨线程块集群（cluster）的内存拷贝与规约；fabric 系列则指向芯片间的互连（如 NVLink/ fabric）通信。对这些特性的理解，需要结合第 2 章线程层次里的 cluster 概念。
