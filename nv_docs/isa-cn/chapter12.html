第 12 章 .pragma 字符串说明

本章描述由 ptxas（PTX 汇编器，即 NVIDIA 的 PTX→SASS 后端编译器）定义的 .pragma 字符串。 .pragma（给 PTX 汇编器/编译器的提示伪指令，类似编译器 pragma）用于向优化后端传递无法用普通 PTX 指令表达的“提示（hint）”， 例如是否展开循环、寄存器溢出到何处、基本块执行频率等。这些提示通常只影响后端优化决策，不改变程序的语义正确性。

在 CUDA 编程语境下，.pragma 出现在 .ptx 汇编层面；普通 CUDA C++ 开发者通常通过 #pragma unroll 等高级写法， 经 nvcc 编译后最终被翻译成等价的底层提示。理解本章有助于在需要手写或精调 PTX、定位性能问题时，精确控制后端行为。

12.1 Pragma 字符串："nounroll"

"nounroll"

在优化后端编译器中禁止循环展开（unroll，即把循环体复制多份以消除循环控制开销的优化）。

语法

.pragma "nounroll";

说明

"nounroll" pragma 是一条用于禁止优化后端编译器进行循环展开的指令。

"nounroll" pragma 可在模块（module）、入口函数（entry-function）和语句（statement）三个层级使用，含义如下：

作用域含义
模块作用域
（module scope）		 禁止展开模块内所有循环，包括出现在该 .pragma 之前的循环。
入口函数作用域
（entry-function scope）		 禁止展开该入口函数体（kernel 函数体）内的所有循环。
语句级 pragma
（statement-level pragma）		 禁止展开“当前基本块恰好是循环头（loop header）”的那个循环。

CUDA 背景：循环展开通常能减少分支、提升 ILP（指令级并行）并隐藏延迟，但会增加寄存器占用。当 kernel 受寄存器数量限制（register-bound）时，过度展开会触发寄存器溢出（spill）到本地内存，反而变慢；此时 nounroll 可用于抑制展开。

注意：为了让语句级 pragma 生效，"nounroll" 指令必须出现在所需循环头基本块中、位于任何指令语句之前。循环头基本块（loop header block）的定义是：支配（dominate）循环体内所有基本块、且是循环回边（backedge）跳转目标的基本块。出现在循环头基本块之外的语句级 "nounroll" 指令会被静默忽略。

PTX ISA 版本说明

于 PTX ISA 2.0 引入。

目标 ISA 说明

需要 sm_20 或更高版本。对 sm_1x 目标会被忽略。

示例

.entry foo (...)
.pragma "nounroll";  // 本函数内不展开任何循环
{
...
}

.func bar (...)
{
...
L1_head:
     .pragma "nounroll";  // 不展开这个循环
     ...
@p   bra L1_end;
L1_body:
     ...
L1_continue:
     bra L1_head;
L1_end:
     ...
}

12.2 Pragma 字符串："used_bytes_mask"

"used_bytes_mask"

用于指示加载（ld）操作数据中被实际使用的字节的掩码（mask）。

语法

.pragma "used_bytes_mask mask";

说明

"used_bytes_mask" pragma 是一条指令，用于根据所提供的掩码指明某次加载操作中“被使用”的字节。 "used_bytes_mask" pragma 必须出现在需要标注“从加载操作中使用了哪些字节”的那条加载指令之前。 如果其后跟随的不是加载指令，该 pragma 会被忽略。

对于没有此 pragma 的加载指令，编译器默认认为加载操作中所有字节都被使用。

操作数 mask 是一个 32 位整数，其置 1 的位表示加载数据中“被使用”的字节。

语义

mask 操作数中的每一位对应一个字节数据，置 1 的位表示该字节被使用。
最高位（most-significant bit）对应数据的最高字节。

// 4 字节加载，仅低 3 字节被使用
.pragma "used_bytes_mask 0x7";
ld.global.u32 %r0, [gbl];     // %r0 的高 1 字节未被使用

// 16 字节向量加载，低 12 字节被使用
.pragma "used_bytes_mask 0xfff";
ld.global.v4.u32 {%r0, %r1, %r2, %r3}, [gbl];  // %r3 未被使用

CUDA 背景：后端可据此对未使用的字节做消除/优化（例如避免无谓的依赖、减少实际访问宽度），从而改善生成的 SASS。该提示不会影响程序结果，只影响后端对“哪些是死字节”的判断。

PTX ISA 版本说明

于 PTX ISA 8.3 引入。

目标 ISA 说明

需要 sm_50 或更高版本。

示例

.pragma "used_bytes_mask 0xfff";
ld.global.v4.u32 {%r0, %r1, %r2, %r3}, [gbl]; // 仅低 12 字节被使用

12.3 Pragma 字符串："enable_smem_spilling"

"enable_smem_spilling"

为 CUDA kernel 启用共享内存溢出（shared memory spilling）。

语法

.pragma "enable_smem_spilling";

说明

"enable_smem_spilling" pragma 是一条指令，用于启用把寄存器溢出（register spilling）到共享内存。 在溢出过程中，寄存器首先被溢出到共享内存；一旦分配的共享内存用满，额外的溢出会被重定向到本地内存（local memory）。 由于共享内存访问比本地内存更快，这可以降低内存访问延迟从而提升性能。

"enable_smem_spilling" pragma 仅允许在函数作用域（function scope）内使用。应用后，它为指定函数启用共享内存溢出。

CUDA 背景：当 kernel 寄存器不足时，ptxas 会把“溢出”的寄存器写入本地内存（实际位于全局/显存的 L1/L2 缓存之外，延迟高）。启用共享内存溢出可把这部分写入改为延迟更低的共享内存，常用于寄存器紧张又追求性能的 kernel。但它会占用共享内存配额，可能限制可同时运行的 block（CTA）数量。

该 pragma 的使用仅在某些特定场景和编译模式下有效。在以下情况下禁止使用该 pragma，并可能导致报错：

  • 逐函数编译模式（per-function compilation）：例如分离编译（Separate Compilation）、设备调试（Device-debug）、含递归函数调用的全程序编译（Whole program with recursive function calls）、可扩展全程序（Extensible-whole-program）；
  • 使用了动态分配共享内存的 kernel；
  • 使用了 setmaxnreg 指令的 kernel。
注意

如果未显式指定 launch bounds（启动配置，如 __launch_bounds__），编译器会假设每个 CTA 使用最大可能的线程数，用以估算每 CTA 分配的共享内存及相应的溢出大小。然而，如果 kernel 实际启动时每 CTA 的线程数少于估算值，每 CTA 分配的共享内存可能超过编译器估算值，从而潜在地限制可在 SM 上启动的 CTA 数量。因此，未指定 launch bounds 而使用该 pragma 可能导致性能回退。建议仅在显式指定 launch bounds 时才使用此 pragma。

PTX ISA 版本说明

于 PTX ISA 9.0 引入。

目标 ISA 说明

需要 sm_75 或更高版本。

示例

.entry foo (...)
{
    ...
    .pragma "enable_smem_spilling";   // 为本函数启用共享内存溢出
    ...
}

12.4 Pragma 字符串："frequency"

"frequency"

指定基本块（basic block）的执行频率。

语法

.pragma "frequency n";

说明

"frequency" pragma 是一条指令，用于指定某基本块被执行线程执行的次数。优化编译器后端将此 pragma 视为一个用于优化的提示（hint）。

操作数 n 是一个 64 位非负整数常量，表示执行频率。

CUDA 背景：基本块执行频率是后端做布局（code layout）、寄存器分配优先级、分支预测与冷热代码分离等优化的重要依据。冷路径（frequency 低）可被放到次要位置以减少指令缓存压力。注意这只是 hint，后端可能因其他约束而偏离。

注意：为使该 pragma 达到预期效果，它应出现在基本块起始处。基本块定义为：仅有一个入口点和一个出口点的直线型（straight-line）指令序列。

PTX ISA 版本说明

于 PTX ISA 9.0 引入。

目标 ISA 说明

所有目标架构均支持。

示例

.entry foo (...)
{
    .pragma "frequency 32";
    ...
}
