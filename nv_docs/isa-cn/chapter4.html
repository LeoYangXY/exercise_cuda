第 4 章 语法（Syntax）

PTX 程序是一组文本形式的源模块（source module，即文件）的集合。PTX 源模块采用汇编语言风格的语法，包含指令操作码（opcode）和操作数（operand）。伪操作（pseudo-operation）用于描述符号与寻址的管理。优化后端编译器 ptxas 负责对 PTX 源模块进行优化并汇编，最终生成对应的二进制目标文件。

背景补充：可以把 PTX 理解为“面向 GPU 的、类汇编的中间语言”。CUDA C/C++ 这类高级语言在编译时并不会直接生成机器码，而是先生成 PTX 文本；安装时（install time）由驱动中的 JIT 编译器（即 ptxas 后端）把 PTX 翻译为目标 GPU 架构的真实指令。因此你写 PTX 时是在写一种“虚拟汇编”，而不是直接写 SM 硬件指令。

4.1 源格式（Source Format）

源模块是 ASCII 文本。各行以换行符（ ）分隔。

所有空白字符（空格、制表符、换行等）彼此等价；除用于分隔语言中的词素（token）外，空白会被忽略。

PTX 源模块可以用 C 预处理器 cpp 来处理。以 # 开头的行是预处理器指令（preprocessor directives）。以下是常见的预处理器指令：

#include, #define, #if, #ifdef, #else, #endif, #line, #file

Harbison 与 Steele 所著的 C: A Reference Manual 对 C 预处理器有详尽的说明。

PTX 区分大小写，且关键字一律使用小写。

每个 PTX 模块必须以一条 伪指令（directive，又称指示符） .version 开头，用于指定 PTX 语言版本；随后必须跟一条 .target 伪指令，用于指定所假设的目标架构。关于这两条伪指令的更多信息，参见“PTX 模块伪指令（PTX Module Directives）”。

directive（伪指令 / 指示符）说明：PTX 中以“.”开头、用于声明或描述结构而非真正产生可执行操作的符号，统称为 directive。例如 .entry 定义一个 kernel 入口函数，.reg 声明寄存器变量，.version / .target 描述模块元信息。它们告诉编译器“怎么组织程序”，而不是“算什么”。它类似于汇编里的伪指令/汇编指示（assembler directive），本身不对应一条机器指令。

4.2 注释（Comments）

PTX 的注释遵循 C/C++ 语法：使用不可嵌套的 /* 与 */ 表示可跨多行的注释，使用 // 表示一条从该处开始、直到下一个换行符（换行符同时结束当前行）为止的注释。注释不能出现在字符常量、字符串字面量，或其他注释之中。

在 PTX 中，注释被视为空白（whitespace）。

4.3 语句（Statements）

一条 PTX 语句（statement）要么是伪指令（directive），要么是指令（instruction）。语句以一个可选的标签（label）开头，以分号（;）结尾。

示例

        .reg     .b32 r1, r2;       // 声明 32 位寄存器 r1, r2
        .global  .f32  array[N];    // 声明全局 float 数组 array

start:  mov.b32   r1, %tid.x;       // 把线程 ID.x 存入 r1
        shl.b32   r1, r1, 2;          // 线程 id 左移 2 位（即乘 4）
        ld.global.b32 r2, array[r1];  // 线程 tid 读取 array[tid]
        add.f32   r2, r2, 0.5;        // 加 1/2
代码说明：这是一个典型 PTX 片段。start: 是标签；mov / shl / ld.global / add 是指令；.reg / .global 是伪指令。%tid.x 是只读特殊寄存器，表示线程在 block 内 x 维度的编号。整段逻辑是“每个线程根据自己 tid 计算下标，从全局数组 array 取出一个 float，再加 0.5”。

4.3.2 指令语句（Instruction Statements）

指令（instruction）由一条指令操作码（opcode）后跟一个逗号分隔的、零个或多个操作数的列表构成，并以分号结尾。操作数可以是寄存器变量、常量表达式、地址表达式，或标签名。指令带有一个可选的保护谓词（guard predicate），用于控制条件执行。保护谓词位于可选的标签之后、操作码之前，写成 @p 的形式，其中 p 是谓词寄存器（predicate register）。保护谓词可选择性取反，写作 @!p。

目的操作数（destination operand）在前，其后跟源操作数（source operands）。

背景补充：谓词寄存器（如 %p0）保存一个真/假值。写 @p add.s32 r1, r2, r3 表示“仅当 p 为真时才执行这条加法”；写 @!p 则表示“仅当 p 为假时执行”。这是 PTX 实现无分支条件执行（branchless 条件执行）的核心机制，可避免 warp 内分支发散（divergence）。
